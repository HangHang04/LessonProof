## 报名与上传

1. 打开官网，注册并登录参赛账号。在上述赛题页面点击“报名”，按实际情况填写队长、单位和团队成员。团队最多 10 人，同一人不能在同一赛题重复参赛。个人开发者也在参赛对象范围内。
2. 在该赛题的“提交方法”页下载**当届统一 Word 模板**，填写行业背景与痛点、技术方案、实施效果。建议作品名称为“LessonProof：实训课程课前验证与交付智能体”。单位与人员信息使用真实信息。
3. 在模板内放入流程图、运行截图、系统调用证据、修订前后对照、测试数据说明、部署与复现方法。附件材料也插入这份文档中。
4. 把可访问的演示视频链接制作成二维码，插入文档。导出 PDF 后，用另一台设备实际扫码检查可播放；同时保留可点击的视频链接方便评审访问。
5. 导出为**一个 PDF**，按 `单位简称-作品名称-队长姓名-队长手机号-日期.pdf` 命名。登录赛题页，在“提交方法”点击“上传”。确认系统显示提交成功并保存回执或截图；修改材料后可再次提交，以末次有效提交为准。

GitHub 是代码与复现入口，比赛作品仍通过赛事网站上传 PDF。项目仓库与视频链接放进申报文档，方便评审核对。

模板请从[赛题的“提交方法”页](http://www.aiinnovation.com.cn/#/trackDetail?id=177)下载，以避免使用旧届模板。网站当前为 HTTP 地址，本次浏览器实际读取成功；提交个人信息前确认地址和登录页面来自官网。

## 正式申报前还需要完成什么

**本地演示与开发测试已经可以做，正式的业务收益数据仍需采集。** 自动化模拟操作不能填成真实教师或学生的人工基线。

| 赛题要求 / 评审重点 | 当前状态 | 下一步 |
| --- | --- | --- |
| 使用如 AgentArts 等平台开发智能体 | 当前为本地 Ollama 与自建编排，AgentArts 待接入 | 获取开发账号后实测；向赛题助手确认自建编排是否符合平台口径 |
| 至少两个现有业务系统或工具，附交互证明 | GitHub 固定来源、本地 Ollama、本地 Git 均有真实调用；远程教学发布待接入 | 申报时准确说明各工具作用；补真实课程仓库审核与教学平台草稿、发布、回读记录会更有说服力 |
| 人工基线与智能体运行对比 | 已有真实自动运行证据，人工记录表尚待填写 | 用相同任务记录人工工时、辅助检查工时、发现问题、误报、漏报和修复结果 |
| 实际应用效果 | 公开课程与开发者模拟操作通过；真实课堂试用待组织 | 请教师或助教核对教学意图，并组织小规模真实试用 |
| 完整提交物 | 代码、运行说明与样本已提供 | 填当届模板，加入实测结果和视频二维码，导出最终 PDF |

当前可报告的是“在三套公开课程上的开发验证结果”；效率提升百分比、教师实际采用率、课堂收益须有试用原始记录支持。网站计分中业务价值量化占 35%、系统集成占 25%、可复制性占 25%、实际应用效果占 15%，应优先补测量与应用证据。

## 用较少精力做一次真实试用

先邀请 2—3 位同学或助教，各完成一份小课程的人工检查，再完成另一份难度相近课程的 LessonProof 辅助检查；交叉安排顺序，避免总是先人工后 AI。教师核对问题判定与修订是否保留教学目标。

使用 [manual_trials.csv](../benchmarks/manual_trials.csv) 记录原始数据。分开记录主动操作时间、等待时间、人工复核时间与整单耗时；保存失败案例和误报，不只保存通过案例。课程中人为设置的问题与来源本来存在的问题分别说明。小样本结果只说明这些任务中的观察，不外推为全校或全行业收益。

可在申报附件中给出人工与辅助检查的成对结果、原始表、统计口径，以及可按任务编号找到的证据包。收费平台若参与实验，记录实际调用费用后再计算成本。
