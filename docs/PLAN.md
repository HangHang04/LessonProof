# LessonProof 推进计划

## 产品目标与首版范围

使用者是实训课程教师、助教或教研人员。任务是对即将交付的课程进行试跑、整改和验收。

首版输入：Markdown 讲义、Jupyter Notebook、CSV 数据，以及明确版本的 Python 环境。首先验证讲师演示路径；练习留白、教学预期报错、随机输出容差由课程负责人预先说明。

业务闭环：接收并固定版本 → 确认试跑步骤与标准 → 执行 → 定位问题 → 审阅修订 → 使用原标准复验 → 审批发布 → 回读核对。

## 推进顺序与验收

| 阶段 | 交付物 | 验收条件 |
| --- | --- | --- |
| M0 本地验收基准 | 三类原创样例、结果校验器、修订复验、执行证据 | 正常案例通过；读错列被发现；预期报错被正确处理；修订通过原标准 |
| M0.1 公开课程基准 | 三套来源固定的课程包、材料检查器、历史修订依据、人工记录表 | 来源可追溯；材料与步骤检查通过；课程执行明确待验证 |
| M1 平台能力验证 | AgentArts 与沙箱探测记录；教学平台读写探测 | 固定版本、全新会话、依赖安装、文件传输、超时和日志获取均有实测结论 |
| M2 课程试跑 | 从讲义生成带出处的步骤，确认后在沙箱执行 | 每次操作可追溯到材料；缺少步骤不会被静默补齐；原材料保持可恢复 |
| M3 问题修复 | 结合讲义、代码、数据和证据提出修订 | 改动可审阅；修改范围受控；验收标准保持锁定；失败保留原因 |
| M4 业务集成 | GitHub 修改审核与教学平台发布回读 | 至少两个现有业务系统真实读写；重复操作不重复发布；版本变化使原审批失效 |
| M5 试用评测 | 人工、普通 AI 辅助、LessonProof 对照结果 | 保存原始工时、成功与失败案例、成本和人工复核记录 |
| M6 参赛交付 | 可运行项目、操作说明、演示视频、PDF 材料 | 演示结果、原始数据、申报数字和版本相互对应 |

M0 的校验器与开发回放是后续沙箱结果的验收基准；自动步骤提取与智能修复单独实现、单独评测。

## 分工

- 项目负责人：确定教学目标和费用上限、在本地配置账号授权、确认验收标准、实际试用并组织后续反馈、确认最终申报材料。
- Codex：调查课程与工具、开发及测试、整理运行证据、设计评测、实现界面和准备交付材料。每次交付说明运行方法、验证结论和未完成环节。

当前已提供 M0/M0.1 基准，以及 M2/M3 的本地实现：工作台确认步骤、WSL + bubblewrap 隔离试跑、本地 Ollama 审阅、教师修订复测、绑定版本的审核、本地 Git 归档和学生课程包回读。使用方法见[验收操作指南](ACCEPTANCE.md)。

M1 的 AgentArts、远程教学平台部分仍待账号实测；M4 当前完成 GitHub 固定来源读取及本地交付，远程修改审核和教学平台发布未完成。M5/M6 需要实际教师试用、独立测试集和比赛材料。付费资源开通与对外发布在范围和成本确认后进行。

## 核心判定规则

1. 验收标准先确定，再执行；修订代码不改变原有通过条件。
2. 每个执行步骤具有稳定 ID，执行顺序与计划一致；额外操作须重新审核计划。
3. 数值优先核对数据和计算结果；M0 使用精确 JSON 输出，浮点容差在支持相关课程时显式定义。
4. 预期报错必须匹配异常类型及约定信息。未知异常不能因为同样“报错”而通过。
5. 缺少步骤、执行中断或基础设施故障标为证据不足；有明确结果冲突则标为失败。
6. 结果校验器不运行课程代码，也不使用课程材料提供的指令改变验收规则。
7. 教师审核绑定具体版本；审核后材料变化须重新检查；发布后回读学生端内容。

## 平台实测清单

- AgentArts：当前账号可用区域、模型调用、工作流调用、工具鉴权和运行日志。
- 沙箱：独立会话与文件空间、目标 Python/依赖版本、资源及超时限制、文件取回、会话结束后的清理行为。课程执行环境与业务系统凭证分离。
- GitHub：读取课程、创建修改供审核、获取审核与版本状态。仓库连接成功不等于产品连接器已实现。
- 教学平台：优先验证 Frappe Learning 的课程读取、草稿写入、发布权限和发布后回读。自行部署成本与运维方式确认后确定方案。
- 网络：云端工具访问本地服务的可达性需要单独验证；任务可由本地协调服务调用云端能力，不预设云端可以访问本机地址。

## 评测与材料真实性

正式测试按课程来源划分开发集与保留测试集。公开历史问题的修复记录只用于人工确定答案，测试时不提供给被测系统。

分别记录：自然存在的问题、试用中新发现的问题、人为设置的故障。M0 样例属于项目自制开发数据，不作为真实教学落地或效率提升的证明。

比较人工检查、人工使用普通 AI 助手、LessonProof；尽量匹配案例难度、使用顺序和资源预算。记录人工操作与复核时间、整单耗时、误报与漏报、错误放行、修复通过率和实际调用成本。正常课程和预期异常必须进入评测。

单人测试先用于可行性判断；多人试用之后再描述适用范围。申报前核对当届比赛时间、平台要求、试点证明口径和官方文档模板。
