# LessonProof 验收操作指南

这一轮主要检查：系统能不能找出讲义里的真实问题，保留教学所需的错误，并把正确版本完整交付。请按教师或学生的视角体验，不需要先研究代码。

## 1. 打开

在项目文件夹打开 PowerShell，执行：

```powershell
.\start.ps1
```

浏览器会打开 [LessonProof 工作台](http://127.0.0.1:8765)。如果已经打开，直接刷新即可。左侧“环境与连接”可查看本地模型与课程环境状态。

## 2. 先体验最完整的案例

1. 在“缺失值与整数转换”卡片点击“开始试跑”。每次都会创建新副本。
2. 阅读“讲义与步骤”。找到 `cast-weight`：这节课原本就要观察转换失败，旧讲义写的是 `ValueError: Cannot convert NA to integer`。
3. 在“下一步”勾选“我已确认步骤、输入数据与教学预期报错”，点击“确认并开始试跑”。电脑上操作区在右侧，手机上排在讲义前。来源核验与模型首次加载可能需要等待；页面会显示实际阶段。
4. 结果回来后，在“运行证据”确认三个步骤的执行符合标准；第二步仍然报错。再看“问题与修订”：AI 应指出异常说明与实际环境不一致。
5. 检查修改对照。预期建议只把讲义更新为 `IntCastingNaNError: Cannot convert non-finite values (NA or inf) to integer`。原始代码、缺失值和验收标准应保持原意。
6. 勾选接受修订，点击“采用修订并复测”。页面变为“版本 2”。复测继续观察同一种教学报错，并使用原验收标准。
7. 复测完成后阅读讲义和运行结果，勾选教师复核框，点击“审核通过”，再点击“生成交付包”。
8. 打开“学生视角”，确认讲义已更新、代码仍保留报错练习。下载课程包，检查其中有 `lesson.md`、`lesson.ipynb`、许可和数据。

在“运行证据”中可以对比两次执行；右侧“验收标准指纹”在修订前后应完全相同。“交付记录”应显示回读一致，并提供本地 Git 版本与文件校验值。

AI 不保证每次措辞相同。若它提出不正确的改动，不要采用；若把完全一致的内容列成问题，可展开“教师复核”，填写依据。运行结果与来源没有通过时，系统不会允许通过这个入口放行。

## 3. 再试两种容易误判的情况

| 操作 | 应该看到什么 |
| --- | --- |
| 新建“数组数据读取与统计”并试跑 | 三步符合标准；形状 `[60,40]`、最大值 `20`、平均值 `"6.14875"`；无需修订即可进入审核 |
| 新建“读懂列表越界的错误信息”并试跑 | 第一格保留 `IndexError`；第二格继续输出长度 `3` 和末索引 `2`；不能把故意的越界访问修掉 |
| 不勾选确认框 | 开始试跑/审核按钮保持不可用 |
| 对同一已交付版本重复操作 | 保留相同交付回执，不创建不同的重复交付 |
| 下载完整证据 | 包内包含来源 API 记录、AI 请求响应、执行结果、课程各版本与固定验收目标 |

## 4. 试一次材料错误

先准备完整课程 ZIP：

```powershell
Compress-Archive -Path .\benchmarks\numpy-data\* -DestinationPath .\work\numpy-data.zip
```

点击“导入课程”，阅读弹出的格式说明，再点击“选择课程 ZIP”。导入这个 ZIP 应检查通过。想测试缺文件时，可以复制此 ZIP，在复制件中删掉 `data/inflammation-01.csv`，再导入。页面应提示缺少数据，不能进入试跑，并提供“重新导入课程”入口。保留原样本目录，便于重复测试。

同一课程版本中，切换标签或点击“刷新”会保留勾选、复核文字和展开状态。修订或运行状态改变后，系统会要求重新确认，避免沿用上一阶段的审核。
